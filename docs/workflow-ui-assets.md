# UI artwork workflow
Two formal request schemas work in Binari: `ui.asset.generate` (`ngs.ui-asset-generate.v1`) accepts `kind` (`logo` or `button`), `title` and an art `prompt`. `ui.asset.import` (`ngs.ui-asset-import.v1`) accepts `kind`, `title` and the `sha256` of the staged PNG. Both include `schemaVersion` and `projectId`. The generation prompt may specify desired native proportions without promising exact generated dimensions. Title: up to 120 Unicode code points and 480 bytes; prompt: up to 2,000 code points and 4,000 bytes, strict UTF-8. No cinematic feature flag controls these families.

Only the trusted local app service can stage via loopback PDS at `POST /v1/ui/ownership/staged` with `{sha256,base64}`. This internal endpoint has no browser or arbitrary-path interface. The app must enforce its owner/session policy before calling. The private scratch stage is limited to 64 unique files, each no more than 8 MiB, and entries older than seven days are pruned on staging. Imports preserve the original byte sequence and pixel geometry. They neither convert nor call ImageGen.

Generation reads only the currently published UI 디자인 Master Concept category, `category.add.4573d0a2e2c659fc0bba561ba5774ac8`, under group.art-design. PDS requires the artifact design digest to match the official snapshot; if the design changes while rendering, the workflow fails instead of silently attributing the asset to the new design. Native ImageGen receives a dedicated transparent-descriptor prompt. Both kinds require a noninterlaced RGBA8 PNG at no more than 4096 pixels per edge, with relevant payload bounds and validated PNG chunks. UI layout should render the actual native aspect; no stretch or nine-slice assets are implied by the contract.

The existing image worker claims and routes the request. PDS holds the save reservation, tells Filex to commit the complete two-file directory, then records task completion. The planner requires the exact result before acknowledging success to Request Service. Outputs are `canonical-files/binari/ui/assets/<officialRequestId>/{asset.png,manifest.json}`. Filex scope `ui` attaches only that canonical top-level folder, using the existing media credential. Before activating an updated unified Filex and PDS through their normal paired deployment, provision the canonical `ui` directory as required for bind mounts (`create_host_path: false`). Use the existing worker service, not another service. Keep deploy verification separate from offline fixture tests.
